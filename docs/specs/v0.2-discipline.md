# Spec — v0.2 Discipline Layer

## Milestone

人 @claude 一个已审 issue 后：builder 自动实现 → 自动开 PR → Codex 自动审 → smoke-test CI 跑 → 停在"待人 merge";修复最多 3 轮自动、超则升级给人。单 issue 的 UIPI 从基线 ~2 降到 ~0(仅剩 @claude 前置放行 + 最终 merge 两个 sanctioned 点)。

## 验收标准(做到什么算对)

1. builder 在 issue 触发后**自动开 PR**(不再只给"Create PR"链接)，PR 正文含 `Closes #N`。
2. PR 一开，**Codex 自动审**(无需手动 @codex review)。
3. 每个 PR 跑 **smoke-test CI**：构建受影响的 tool + 跑其 `node --test`；红则挡住"可 merge"。
4. builder 能自己跑测试(allowedTools 含 `npm test` / `node --test`)，开 PR 前自验。
5. 修复轮数**机械计数**(label 或 `loop-ledger.json`)，达 3 轮打 `needs-human` 并停。
6. **触发治理**：builder 只响应写权限者的 @claude **评论**(移除 `issues: opened` 自动触发)。
7. 移除临时的 `show_full_output`。
8. 度量：跑一个全新测试 issue，`loop-run-log.md` 记录该 issue 的 human escalations(UIPI) = 0。

## 不做清单(本轮边界)

- 不做多-issue triage / 去重 / 优先级(v0.3)。
- 不做 release pipeline / tag / notes(v0.5)。
- 不做多 agent 并行开发。
- 不引入第三家厂、不改 vendor 分工(builder=Claude / reviewer=Codex)。
- 不做自动 merge。

## 拆解为 issues

- #A smoke-test CI + builder 可跑测试(allowedTools)
- #B builder 自动开 PR
- #C Codex 自动审触发
- #D 修复轮数上限(label / ledger 计数)
- #E 触发治理(移除 issues:opened) + 清理 show_full_output + docs 约定
