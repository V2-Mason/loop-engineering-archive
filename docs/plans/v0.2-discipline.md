# Plan — v0.2 Discipline Layer

对应 spec：`docs/specs/v0.2-discipline.md`。

## Correctness & Stability(执行前提)

1. **方向由人写的 spec 给定,agent 只执行**;走偏由三道闸门兜底(Codex intent-check / smoke-CI 客观判据 / 人 merge 读 diff)。
2. **Constitution 与 Product 分开**：本轮 #A–#E 多为 constitution 级(改 agent 行为的文件),**由人手写、从严审、Mason 逐个 merge,不走自主 builder**;自主 builder 的狗粮留给 v0.3+ 的产品功能 issue。
3. 早期不稳可接受,靠"小步/可逆/人 merge + 每次偏差回填规则 + 客观闸门兜底 + 返工率逐轮降"来收敛。

风险分层:
- 高危(改坏则 loop 瘫痪)：workflow 触发/认证/allowedTools、loop-constraints → 人手写。
- 较安全(纯新增)：smoke.yml → 可选择性狗粮,仍从严审。

## 步骤

一次性 setup(本 PR)：
- `docs/product/roadmap.md`、`docs/specs/v0.2-discipline.md`、本文件。
- `mason-loop/loops/retro-001.md`(v0.1 收尾复盘)。
- 建 GitHub Milestone "v0.2 Discipline" + Projects 看板 + issues #A–#E。

功能项(每项一个 issue,顺序 1→2→3 打通自动化骨架,再回填 4→5)：

1. **#A smoke-test CI**：新增 `.github/workflows/smoke.yml`,`pull_request` 上构建受影响 tool + 跑 `node --test`;`claude.yml` 的 allowedTools 加 `Bash(npm test)` / `Bash(node --test)`。
2. **#B builder 自动开 PR**：调研 `claude-code-action` 的 PR 自动创建选项(如 PR 模式 / `track_progress`),或让 builder 用 `gh pr create`;实现路径在该 issue 内定。
3. **#C Codex 自动审**：首选 Mason 在 Codex 设置开 Automatic reviews;备选加 `pull_request: opened` 时评论 `@codex review` 的 workflow(注意 bot 触发链路的坑,需实测)。
4. **#D 修复轮数上限**：用 `loop-guard` 的 `loop-ledger.json` 或小 workflow 计数,达 3 轮打 `needs-human` 并停。
5. **#E 触发治理 + 清理**：`claude.yml` 移除**整个** `issues:` 触发块(opened+assigned,只删 opened 留后门)、移除 `show_full_output`(public repo 会泄露全量日志);`AGENTS.md`/docs 记"triage → @claude 放行"约定。可选纵深:`if:` 加 author_association 白名单、加 `concurrency` 组。
6. **#F 分支保护 ruleset(来自 review)**：`ruleset-main-protection.json` 加 `{ "context": "smoke" }`、`required_approving_review_count>=1`、`required_review_thread_resolution:true`、`strict:true`;并**用 `gh api` 应用 ruleset**(当前 repo 零生效保护,不 apply 则一切"红"都挡不住 merge)。此项含 L2、需 Mason 定"Codex 红评审是否应硬挡 merge"。

## 验收

merge 完 #A–#E 后,造一个全新测试 issue,Mason 只做两个动作(审完 @claude、最后 merge),中间不碰;确认 PR 自动开、Codex 自动审、smoke 跑过、修复自动且不超 3 轮。`loop-run-log.md` 里该 issue UIPI = 0;不引发 revert/补丁。
